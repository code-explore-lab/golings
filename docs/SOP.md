# 学习、维护与复核 SOP

## 解题流程

1. 用 `gopath init [目录]` 初始化；显式目录用 `gopath --workspace <目录> next`，或进入目录后运行。初始化不覆盖现有课程文件。
2. 阅读 `next` 显示的 README、目标、起始代码与测试。优先完成 01–06 前置，再投入 07–10 Kubernetes 扩展。
3. 修改学习目录中的 Go 代码和部署资产；不修改必需测试，可以添加自己的回归测试。
4. `gopath check [id]` 会显示原始测试诊断。依赖第一次下载可能耗时。不要通过删除测试、硬编码样例或放宽断言解决题目。
5. 卡住时 `gopath hint [id]`，每次一条。查看提示只记录使用次数。
6. 07–15 单测通过后是 [~]。按题目 README 准备真实环境，运行 `gopath check --integration <id>`。缺环境、测试跳过、没有执行 integration 测试都会失败。
7. 记录实验结果并复盘口述问题：现象、原因、预测、故障排查。自动检查不代替这一环节。
8. `list` 和 `stats` 可跨进程读取进度；相关文件变化后旧成绩变 [!]，重新检查。默认 next 会停在首个未完成题，可指定其他 ID 继续离线学习。

## 外部环境

Kubernetes 练习明确使用 minikube context，在测试创建的独立 namespace 操作；08/09 的 CRD 是集群资源，须按各题 README 显式安装，测试不自动更改其他集群。练习完成后按说明清理测试或手工实验资源；不要删掉已有共享 CRD。

Linux 实操可以在 WSL2/Linux 进行；不要将 Windows fixture 单测成功视为 namespace/cgroup 实验成功。Prometheus/Grafana 题提供服务、配置与实际 HTTP API 检查，需先运行相应服务。根据本地端口设置题目支持的环境变量。

## 重置与故障处理

`gopath reset <id>` 会列出精确的管理文件。只有输入 `RESET <id>` 才覆盖文件和清除该题完成/提示记录；空输入、EOF 或其他输入均取消。额外文件不会删除，因而新增的 .go 文件仍可能影响后续编译。需要保留的解答先备份或提交 Git。

必需测试不见或被改时，check 会拒绝通过。可从同版本课程 tests 模板恢复对应文件，或者确认后 reset 整题。请注意所有模板会去掉 .txt 后缀。

进度 JSON 损坏或版本不支持时会报错，不会静默改写。先保留该文件用于排查。恢复自己的备份后重试；若主动决定放弃历史成绩，可以在确认路径后自行另存或移走该文件。

初始化冲突时选择一个新的学习目录；不要删除不清楚归属的代码。Go 测试有每次两分钟的运行超时，整个进程包括下载最长十分钟；Ctrl+C 取消当前检查，不记录通过。

检查期间修改相关文件会要求重新检查；go.mod 自动更新也需重跑一次，go.sum 自动生成不影响本次验收。同一工作区的 check、hint、reset 会互斥。报 busy 时等待另一个终端结束；强制结束进程可能留下 `.gopath/write.lock`，先核对其中的 PID，确认没有 GoPath 写入操作仍在运行，才手动移走这个精确文件。不要直接删除整个 .gopath 目录。reset 等待确认时也持有锁。

## 新增和评审练习

按 [CONTRIBUTING](../CONTRIBUTING.md) 创建独立目录。先明确主概念和可验证结果，再写行为测试、参考解答、起始缺陷和渐进提示。使用注入依赖、fixture、httptest、fake Kubernetes 客户端，避免随意 sleep 与公网依赖。

维护者依次执行格式化、vet、核心测试和显式的课程作者检查。新增实操题须提供 integration tag 与 TestIntegration 测试；缺环境明确失败而非 Skip。评审时检查解答是否幂等、取消是否传播、资源是否有界、错误是否保留原因、资源清理是否限制在测试创建的范围。

每次变更更新 JD 映射及对应说明。验收报告分别列出实际执行的离线检查、仅编译的实操检查和真正运行的实操结果，不混写。
